# Krishti AI V14.1 — Login & Authentication Fix

## Frontend
- Email/password login and account creation are wired to Firebase Authentication.
- Forgot-password flow uses Firebase password reset email.
- Phone login uses Firebase SMS OTP + reCAPTCHA.
- Added detailed Firebase error messages for email, password, phone, OTP, quota, domain and network errors.
- Phone reCAPTCHA is rendered visibly to make browser verification more reliable.

## Important Firebase Console setup
Firebase Authentication must have the providers enabled. The app code cannot enable providers in a Firebase project automatically.

1. Firebase Console → Authentication → Sign-in method → enable **Email/Password**.
2. Enable **Phone** provider.
3. Authentication → Settings → SMS region policy → allow the countries you want to support (for India, allow India/IN).
4. Authentication → Settings → Authorized domains → add the real deployed domain.
5. For local phone-auth testing, use a deployed/authorized HTTPS domain or Firebase's testing phone numbers. Phone auth on web requires app verification/reCAPTCHA.

Google continues to use the existing working provider.

## Backend
No password or OTP is stored by Krishti's Express backend. Firebase Authentication remains the authentication authority, which is the safer architecture for credentials and SMS verification.
