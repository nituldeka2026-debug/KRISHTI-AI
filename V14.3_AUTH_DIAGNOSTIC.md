# Krishti AI V14.3 — Firebase Auth Diagnostic Fix

## What changed
- Added exact Firebase auth error-code diagnostics for Phone OTP.
- `auth/operation-not-allowed` now points to the Phone provider **and SMS region policy** instead of assuming the provider is disabled.
- Shows the current hostname and Firebase project ID in the Phone OTP error, making domain/project mismatches easier to identify.
- Added clearer messages for unauthorized domain, SMS quota, and reCAPTCHA failures.
- Firebase Auth language is explicitly set to English.
- Service worker cache is bumped to `krishti-v14.3-auth-debug` and old Krishti caches are deleted on activation, preventing stale auth JavaScript from being served.

## Important Firebase setting to verify
Firebase's current web Phone Auth documentation requires a Phone provider, an authorized domain, and an SMS region policy. For a new project, the SMS region policy may allow no regions by default. Ensure **India** is allowed under Firebase Console → Authentication → Settings → SMS region policy.

## Testing
1. Deploy this V14.3 build to the authorized Render domain.
2. Hard refresh once.
3. Try Phone → Send OTP.
4. If Firebase still rejects it, the UI will now show the exact error code and relevant diagnostic.
5. For development, Firebase test phone numbers can be used to avoid real SMS quota/throttling.
